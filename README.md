# 派生表重建控制台 · daily_settlement

一个本地可运行的、按「代次 + 分区核对 + 读入口切换」组织的派生表重建控制台。
没有外部依赖：Node 内置 `node:sqlite` 持久化，原生 HTTP 服务，前端是原生 ES 模块。

每次重建都绑定一组不可变的输入 **源数据版本 × 规则版本**，得到一个递增的 **代次**。
分区在真实源行上扫描、聚合、写检查点，再由**独立的第二遍扫描**核对。
只有当前代次 12/12 分区核对通过，读入口才原子切换；旧代次的结果保留用于对比，
回收前会检查是否还有读者持有租约。

## 运行

需要 Node ≥ 22.5（`node:sqlite` 内置）。

```bash
npm start          # http://localhost:4173
npm run dev        # 同上，文件变更自动重启
npm test           # 24 个测试：真实分区计算、代次门禁、暂停恢复、租约回收、HTTP 路由
PORT=8080 npm start
```

首次启动会在 `.data/console.db`（可用 `DB_PATH` 覆盖）建库，并同步计算一次
「代次 1 · 源 v1 / 规则 v1」作为当前可见版本。网页轮询 `/api/state`：任务运行时 450ms，空闲时 1.6s。

## 页面能做什么

| 要求 | 页面上的位置 |
|---|---|
| 发起两次交错的重建 | 「发起重建」表单；可先发慢任务、再发快任务，两个任务并行推进 |
| 暂停某个分区 | 任务卡片中任一分区的「暂停」，检查点冻结，可「继续」 |
| 查看被替代任务 | 「任务与分区」里 `被代次 N 替代` 的卡片、「代次历史」的状态列 |
| 查看实际可见版本 | 顶部「实际可见版本 · 读入口」：代次、源/规则绑定、净额、切换时间 |
| 恢复未完成的当前任务 | 失败或暂停的**当前**代次卡片上的「恢复当前任务」 |
| 保留旧代次用于比较 | 「代次对比」按分区并列新旧净额，附表格视图 |
| 回收前检查读者 | 「读者租约」打开旧代次；「代次历史」的「回收」由服务端复查租约 |

「故障与耗时注入」中可逐分区设置构建/复核耗时、单次或持续故障、以及**篡改构建产物**
（只能被独立复核发现）。三个预设按钮分别配置：两个交错任务、分区失败 + 重试、产物被篡改。

示例流程：

1. 点「示例：两个交错任务」→ 发起慢任务（代次 2）。
2. 在任务 2 中暂停某个分区，观察进度与行数停住；卡片标注「检查点保留」。
3. 把耗时调小，选源 v3 / 规则 v3，发起代次 3（快任务）。
4. 代次 3 先到 12/12 → 读入口切到 3，顶部大号数字变为 3。
5. 继续被暂停的分区。代次 2 最后完成，但只标记「已被替代」，结果保留可对比。
6. 用「读者租约」打开代次 2；此时代次历史里点「回收」会被服务端拒绝并说明是哪个读者。
   关闭租约后再回收，分区产物释放，汇总结果保留用于对比。

## 为什么不是「页面状态变化」

- 进度来自真实扫描：每个 tick 每个活动分区都会调用 `scanOrders()` 扫一段源订单，
  `rows_done` 和 `cursor_index` 是真实行位置；暂停时游标不动，继续时从游标接着扫。
- 完成不是按钮给的：分区先在构建阶段产出聚合值，再进入复核阶段做**第二次独立扫描**，
  逐字段比对 8 个指标（含校验值）。构建时注入的篡改只有复核能发现。
- 读入口切换由引擎事务完成：12/12 全部 `verified` 才 `promote`；否则指针不动。
- 旧任务晚完成也进不了读入口：完成时若已有更新代次在推进或已可见，只落 `superseded`。

## 合成数据

`server/synthetic.js` 生成 360 天 × 1,200 单 = 432,000 条不可变订单。
表按 **12 个分区 × 30 天输出窗口** 切分；每个分区还要回溯 90 天，
以覆盖退款延迟窗口，所以扫描行数随分区号增长（36k → 144k）。

- **源版本**：v1 原始快照；v2 补录迟退单（退款日 31–85 天）；v3 再补录并标记冲正/拒付退款（冲正不计入）。
- **规则版本**：v1 60 天窗口 / 2.9% 费率 / 排除争议；v2 75 天 / 2.4% / 计入争议；v3 45 天 / 3.1% / 排除争议。

所有数据由订单下标确定性生成，没有随机源；同一 (源版本, 规则版本, 分区) 永远得到同一结果，
所以「中断后继续」与「一次算完」必须逐字段相等（有测试保证）。

## 结构

```
server/
  synthetic.js  确定性源数据、分区定义、分块扫描 scanOrders()、聚合与校验值
  db.js         SQLite 表结构（builds / partitions / generations / read_pointer / leases / events）
  engine.js     批量 tick 引擎：填充并发槽、推进构建/复核、结算与代次门禁、读入口切换
  app.js        命令与状态序列化：发起、暂停/继续/重试、恢复任务、租约、回收
  support.js    规则与设置读取、选项校验、阶段耗时/故障计划、金额格式化
  index.js      HTTP JSON API + 静态文件
public/
  index.html    控制台页面
  styles.css    明/暗两套 token（分类色经过色盲与对比度校验）
  app.js        轮询与渲染，含 SVG 分区对比图与悬停提示
tests/
  engine.test.js 源数据与分区、代次门禁、暂停恢复、租约回收
  api.test.js    HTTP 路由（含分区子路由不被集合路由吞掉的回归测试）
```

### 关键表

- `builds`：一次任务 = 一个代次，绑定 `source_version` / `rule_version`，`UNIQUE(table_name, generation)`。
- `partitions`：每个分区的状态、阶段、真实游标 `cursor_index`、构建聚合 `agg`、复核聚合 `verify_agg`。
- `generations`：代次台账；完成时写 `summary`，回收时只清分区产物、保留 `summary`。
- `read_pointer`：唯一的读入口，`switched_at` 记录切换时间。
- `leases`：读者租约（TTL），`released_at IS NULL AND expires_at > now` 视为活跃。
- `events`：所有关键动作的审计日志，页面「运行日志」直接读取。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 页面渲染所需的全部状态 |
| POST | `/api/builds` | 发起重建：`{sourceVersion, ruleVersion, note, options}` |
| GET | `/api/builds` / `/api/builds/:id` | 任务列表 / 单个任务 |
| POST | `/api/builds/:id/pause` · `/resume` | 暂停 / 恢复当前任务 |
| POST | `/api/builds/:id/partitions/:no/pause` · `/resume` · `/retry` | 单分区操作 |
| POST | `/api/leases` | 打开代次并持有租约 `{generation, readerId, ttlMs}` |
| DELETE | `/api/leases/:id` | 释放租约 |
| POST | `/api/generations/:generation/reclaim` | 回收旧代次（活跃租约时 409） |
| POST | `/api/settings` | 默认耗时与并发 |

冲突一律返回 409 和中文原因；回收被拒时额外返回 `readers: [{readerId, expiresAt, purpose}]`。

## 设计取舍

- 引擎是**单进程定时器 + `BEGIN IMMEDIATE` 事务**推进所有任务，而不是每个分区一个 worker。
  这样便于演示与测试（可注入时钟逐 tick 推进），也避免 SQLite 写争用；扫描本身仍是真算。
- 故障注入只影响指定阶段与尝试次数，不会污染复核扫描；篡改则是**故意写坏构建产物**，
  用来证明复核不是走过场。
- 回收只释放分区产物（`agg`/`verify_agg`/`verified`），代次级 `summary` 和审计记录永久保留。
